使用说明

环境要求

项目要求
服务端Spigot / Paper 及其兼容核心
版本支持Minecraft 1.8.8 ~ 1.21.4（含 1.20.5 / 1.20.6 / 1.21.x 系列，1.20.5+ 通过新适配器支持）
运行环境Java 11 或更高版本（1.20.5+ 服务端按其自身要求使用更高版本 Java；自行编译插件需 JDK 21）

可选软依赖（不装也能运行，装上可解锁扩展功能）：

  • Vault：经济系统
  • PlaceholderAPI：聊天 / 计分板变量
  • Citizens：加入游戏 NPC
  • Parties / PartyAndFriends / Spigot-Party-API-PAF：队伍系统
  • SlimeWorldManager / AdvancedWorldManager：更快的世界地图加载与还原

安装与授权

  1. 将插件 jar 文件放入服务端的 plugins 文件夹。
  2. 启动一次服务端，让插件生成配置文件和语言文件，然后停止服务端。
  3. 编辑 plugins/BedWarsHeypixel/config.yml：
    • 在 license-key 中填入你的授权密钥（本插件为付费授权插件，无有效密钥无法启动）。
    • 根据你的服务器规模设置 serverType（MULTIARENA / SHARED / BUNGEE）。
    • 设置默认 language 语言。
  4. 重新启动服务端，等待授权验证通过后插件即可正常启用。
    授权密钥为空、无效或校验失败时，插件会输出错误日志并自动禁用。
  5. 使用 /bw setLobby 设置主大厅，再按下方“竞技场搭建”创建地图。

提示：每次修改配置文件后可使用 /bw reload 热重载，无需重启服务端。

经验模式说明

  • 在 config.yml 中开启经验模式后，游戏内拾取的资源（铁锭、金锭、钻石、绿宝石）会按照经验转换配置的比例自动转换为经验。
  • 玩家可在 经验商店（shopxp.yml）中使用经验购买物品。
  • 队伍升级包含经验队伍增益配置，通过队伍经验提升全队增益效果。
  • 经验模式同样支持击杀、胜利等行为获得经验，具体奖励可在 levels.yml 中调整。

新道具玩法说明

  • 救援平台：在悬空时使用，脚下生成 5×5 镂空十字粘液块平台，可抵消跌落伤害，平台持续 15 秒后消失，且不可被破坏。
  • 回城卷轴：使用后进入 5 秒回城倒计时（伴有粒子特效），期间移动或丢弃物品会取消，倒计时结束后传送回队伍出生点。
  • 防御墙：在面前生成 3×5 的砂岩墙体，支持斜向放置；前方被遮挡时会自动回退到身后生成。
  • 隐身药水：提供隐身效果，并添加了更大的粒子效果，避免“隐身根本看不见”的问题。

常见问题

Q：插件启动时报错 "No license key configured"？
A：请在 config.yml 的 license-key 中填写有效的授权密钥，并重启服务端。

Q：修改了配置需要重启服务端吗？
A：不需要，直接使用 /bw reload 即可热重载全部配置。

Q：支持哪些版本？
A：支持 Minecraft 1.8.8 ~ 1.21.4 的 Spigot / Paper 服务端，需要 Java 11+（1.20.5+ 通过新适配器支持；注意 1.20.5+ 物品标识改用 PersistentDataContainer，与旧版本物品 tag 不互通，银鲛鱼 / 铁傀儡召唤物在 1.20.5+ 使用原版 AI，行为略有差异）。

Q：如何快速搭建一个竞技场？
A：依次执行 /bw setLobby → /bw setupArena <名称> → /bw autoCreateTeams <数量> → 在世界中按搭建命令设置出生点、床、商店、资源生成器等 → /bw save → /bw enableArena <名称>。

Q：事件加血、快捷栏预设等 26.9 新功能在哪配置？
A：事件加血在 healthadd.yml，快捷栏预设（测试阶段）在 fastbuy.yml，游戏总时长限制、隐身增强、4/5 级资源点开关等在 config.yml。详见 配置文件详解 与 详细使用教程。

纯插件详细使用教程

本教程面向服主，从零开始带你完成安装、授权、搭建竞技场到配置 26.9 全部新功能的完整流程。更细的配置项说明见 配置文件详解，指令与权限全表见 指令与权限。

一、环境要求

项目要求
服务端核心Spigot / Paper 及其兼容核心
Minecraft 版本1.8.8 ~ 1.21.4（26.9 新增支持 1.20.5 / 1.20.6 / 1.21 / 1.21.1 / 1.21.2 / 1.21.3 / 1.21.4）
Java11 或更高（1.20.5+ 核心按其自身要求，通常为 Java 21）
自行编译插件需要 JDK 21

可选软依赖（不装也能运行，装上可解锁扩展功能）：

  • Vault：经济系统
  • PlaceholderAPI：聊天 / 计分板变量
  • Citizens：加入游戏 NPC
  • Parties / PartyAndFriends / Spigot-Party-API-PAF：队伍系统
  • SlimeWorldManager / AdvancedWorldManager：更快的世界地图加载与还原

1.20.5+ 版本注意：物品标识改用 PersistentDataContainer（与旧版本物品 tag 不互通）；银鲛鱼 / 铁傀儡召唤物使用原版 AI，行为略有差异。

二、下载与安装

  1. 获取 BedWarsHeypixel 26.9.1 插件 jar 文件。
  2. 将 jar 放入服务端的 plugins 文件夹。
  3. （可选）安装上述软依赖插件。
  4. 启动服务端。

三、首次启动

  1. 启动服务端，插件会尝试生成配置文件与语言文件。
  2. 首次启动时 license-key 为空，插件会输出 "No license key configured" 之类的错误日志并自动禁用——这是正常现象，先停止服务端进行下一步配置。
  3. 确认 plugins/BedWarsHeypixel/ 目录下已生成：
    • config.yml（主配置）
    • shop.yml / shopxp.yml / fastbuy.yml / healthadd.yml
    • upgrades2.yml / upgrades3.yml / generators.yml / signs.yml / levels.yml
    • 语言文件夹

四、授权激活

本插件为付费授权插件，无有效密钥无法启动。

  1. 编辑 plugins/BedWarsHeypixel/config.yml： 
    license-key: "你的授权密钥"    # 填入购买获得的密钥
  2. 同时确认服务器类型（决定本插件的工作模式）： 
    serverType: MULTIARENA   # MULTIARENA=多竞技场综合服 / SHARED=与其他插件共存 / BUNGEE=BungeeCord 专用
  3. 重启服务端，等待授权验证通过后插件正常启用。密钥为空、无效或校验失败时，插件会输出错误日志并自动禁用。
  4. 授权通过后，控制台 / 日志中可以看到插件版本与启用成功信息。

⚠️ 授权验证发生在插件启用阶段，修改密钥后必须重启服务端，/bw reload 不能代替。

五、语言选择

26.9 起语言系统仅保留三种：简体中文（zh_cn）、繁体中文（zh_tw，26.9 新增）、英文（en）。

  1. 编辑 config.yml 设置服务器默认语言： 
    language: zh_cn
  2. 重启服务端或执行 /bw reload。
  3. 玩家可用 /bw lang 切换自己的个人语言（同样只有三种可选）。

所有提示消息可在语言文件夹对应文件（如 zh_cn）中修改。例如 26.9 新增的胜利副标题：

GAME_END_WIN_TIME_SUBTITLE: "&a&l{team} &7获得胜利, 用时 &f{time}"

六、创建竞技场（/bw setup 流程）

以下流程在 MULTIARENA 模式下操作。准备一张建好的地图世界（每个队伍区域包含出生点、床、商店位、资源点，以及一个等待大厅区域）。

第 1 步：设置主大厅

在大厅世界站好位置后执行：

/bw setLobby

BUNGEE 模式下无需设置主大厅。

第 2 步：进入搭建模式

在要制作为竞技场的地图世界内执行：

/bw setupArena arena1

进入搭建会话后，你会在该世界内获得搭建工具与提示。

第 3 步：创建队伍

推荐自动创建（例如 4 队）：

/bw autoCreateTeams 4

或手动创建 / 移除：

/bw createTeam red
/bw removeTeam red

设置每队人数与最大建造高度：

/bw setMaxInTeam 4       # 每队 4 人（如 4v4v4v4）
/bw setMaxBuildHeight 128

第 4 步：设置等待与观战区域

站在等待大厅内 / 门口分别执行：

/bw setWaitingSpawn      # 等待大厅出生点（玩家排队站立位置）
/bw waitingPos           # 等待大厅区域（两个对角点各执行一次）
/bw setSpectSpawn        # 观战出生点

第 5 步：设置队伍要素（每队各做一遍）

走到对应位置后执行（red 换成实际队伍颜色）：

/bw setSpawn red         # 队伍出生点
/bw setBed red           # 看向床执行，设置床位置
/bw setShop red          # 站在商店 NPC 位执行
/bw setUpgrade red       # 站在队伍升级 NPC 位执行

第 6 步：添加资源生成器

站在铁 / 金 / 钻石 / 绿宝石生成点执行：

/bw addGenerator iron
/bw addGenerator gold
/bw addGenerator diamond
/bw addGenerator emerald

放错了可移除：/bw removeGenerator iron。

第 7 步：其他设置与保存

/bw setType 4v4v4v4      # 设置竞技场类型（队伍规模）
/bw setKillDrops         # 站在期望位置执行，设置击杀掉落物点
/bw save                 # 保存竞技场并退出搭建会话

第 8 步：启用竞技场

/bw arenaList            # 确认 arena1 已保存（默认禁用）
/bw enableArena arena1   # 启用后玩家即可加入

之后玩家通过 /bw join arena1、牌子或 /bw gui 加入游戏。

调试技巧（26.9 修复后可放心使用）

/bw start debug          # 进入调试模式，开局倒计时缩短
/bw time add 600         # 事件倒计时加 600 秒，快速推进到下一个事件

26.9 修复：/bw time add 不再导致事件卡死；计数归零立即推进事件，且每次最多推进到下一个事件（不会跳过床摧毁阶段），重复输入可继续推进。

八、26.9 各功能配置方法

以下均在 plugins/BedWarsHeypixel/ 下编辑对应文件，改完执行 /bw reload。

1. 事件加血（healthadd.yml）

游戏开始后定时对全场存活玩家加血，防止后期被一波打崩。默认 2 次（第 5、10 分钟各 +5 颗心）。

health-add:
  enabled: true
  default-amount: 10          # 单位：半心，10 = 5 颗心
  events:                     # 可配 1~4 次，每次时间与血量可单独配置
    1:
      time-minutes: 5
      time-seconds: 0
      amount: 10
    2:
      time-minutes: 10
      time-seconds: 0
      amount: 10
  • 想改加血时间：改 time-minutes / time-seconds（如 time-minutes: 3, time-seconds: 30 = 3 分 30 秒）。
  • 想改加血量：改 amount（半心；amount: 6 = +3 颗心）。
  • 想加到 4 次：仿照格式新增 3:、4: 条目。
  • 想关闭：enabled: false。
  • 触发时全竞技场广播 &a全体加血 &7(+{hearts} 颗心) 并播放音效（文案可在语言文件改）。
  • 计分板自动集成：加血时间早于下一个事件链事件时，事件行显示加血倒计时。

2. 游戏总时长限制（config.yml）

game-duration-limit: 60   # 分钟；到时强制结算；<=0 关闭

3. 隐身增强（config.yml）

invisibility-enhance:
  enabled: true           # 开启后：非队友完全看不到隐身玩家（含手持物品）；
                          # 队友可见头顶名字标签；未蹲下时向队友发送粒子，蹲下即隐藏
  particle-interval: 4    # 粒子发送间隔（tick）
  particle-amount: 3      # 每次粒子数量

粒子仅发送给队友，降低网络开销；Tab 名牌按队伍区分显示。

十、常见问题

Q：启动报 "No license key configured"？
A：在 config.yml 的 license-key 填入有效授权密钥后重启服务端（/bw reload 无效）。

Q：改了配置一定要重启吗？
A：一般不用，/bw reload 即可；但 license-key、serverType、language 等启动级选项需重启。

Q：搭建命令全部提示无权限 / 未在会话中？
A：搭建命令必须在 /bw setupArena <名> 进入搭建会话后、在对应世界内使用；并确保你有 bw.setup 权限（或 OP）。

Q：竞技场保存了但玩家进不去？
A：新保存的竞技场默认禁用，执行 /bw enableArena <名>；同时确认 /bw setLobby 已设置（非 BUNGEE 模式）。

Q：事件加血没触发？
A：检查 healthadd.yml 的 enabled 是否为 true、events 时间与 amount 是否大于 0，改后 /bw reload；加血按游戏开始后计时，等待阶段不算。

Q：快捷栏预设重进后丢失？
A：测试阶段功能的数据保存在内存中，属已知限制，重进后重新设置即可；不稳定可 fastbuy.yml 中 enabled: false。

Q：怎么关闭限时 / 调整时长？
A：config.yml → game-duration-limit（分钟，<=0 关闭）；配套调整 generators.yml IV/V 级 start 与床摧毁时间可获得合理的对局节奏。

Q：1.20.5+ 服务端有什么要注意的？
A：物品标识改用 PersistentDataContainer（与旧版本物品 tag 不互通）；银鲛鱼 / 铁傀儡召唤物使用原版 AI，行为略有差异。其余无感知。

Q：语言怎么只剩三种？
A：26.9 起仅保留 zh_cn / zh_tw / en，其余 11 种已移除；language 与 /bw lang 只能三选一。

Q：Shift+点击购买一组扣多少钱？
A：按单价比例计价。例：羊毛 16 个 / 4 铁，Shift+点击买 64 个扣 16 铁。

更多问题见 常见问题 FAQ。

healthadd.yml（事件加血，26.9 新增）

可配置游戏开始后 1~4 次全体加血事件；不需要时将 enabled 设为 false 或删除全部 events 条目即可关闭。

默认配置（2 次事件：开局后第 5 分钟、第 10 分钟，每次 +5 颗心）：

health-add:
  # 总开关
  enabled: true
  # 默认加血量（单位：半心）。10 = 5 颗心。单个事件未写 amount 时使用该值。
  default-amount: 10
  # 事件列表：可配置 1~4 次；每个事件的触发时间与血量均可单独配置
  events:
    1:
      time-minutes: 5    # 游戏开始后第 5 分钟
      time-seconds: 0
      amount: 10         # +5 颗心（10 半心）
    2:
      time-minutes: 10   # 游戏开始后第 10 分钟
      time-seconds: 0
      amount: 10

说明：

  • amount 单位为半心，amount: 6 即 +3 颗心。
  • 触发时会全竞技场广播提示并播放音效，消息可在语言文件中修改（默认简中文案：&a全体加血 &7(+{hearts} 颗心)）。
  • 自动集成到计分板事件显示：当加血时间早于下一个事件链事件（如钻石 II 级、床摧毁等）时，事件行会显示加血事件倒计时。
  • 时间与血量不合法（<=0）的事件会被忽略；事件按触发时间先后排序执行。

功能说明

26.9 新增功能

快捷栏预设（测试阶段功能）

  • 开启方式：fastbuy.yml → enabled: true（默认开启）。
  • 入口：打开快捷购买界面，点击红石图标（默认槽位 45，icon.slot 可改）进入预设设置界面。
  • 玩法：为每个商店类别设置“购买后物品自动放入的快捷栏槽位（0-8）”。之后购买该类别物品时，物品自动移位到指定快捷栏槽位；若目标槽位已有物品，则两者交换。
  • 用途：羊毛 / 石头等常用物资买来后自动落到位，省去手动整理快捷栏的时间。
  • 注意：
    • 测试阶段功能，预设数据按玩家保存在内存中，重进服务器后需重新设置。
    • 界面全部文本与图标（标题、清除按钮、返回按钮等）均可在 fastbuy.yml 自定义。
    • 若出现不稳定情况，可将 enabled 设为 false 关闭。

事件加血（healthadd.yml）

  • 作用：游戏开始后按配置时间对场上所有存活玩家触发全体加血，为后期对局续命、避免被一两波消耗打崩。
  • 默认：2 次事件（开局后第 5 分钟、第 10 分钟），每次 +5 颗心（amount=10 半心）。
  • 可配：1~4 次事件；每次的 time-minutes / time-seconds 与 amount 均可单独设置；enabled: false 或清空 events 即关闭。
  • 计分板集成：当加血时间早于下一个事件链事件（钻石 / 绿宝石升级、床摧毁等）时，计分板事件行显示加血事件倒计时，例如“全体加血 03:24”。
  • 触发表现：全竞技场广播 &a全体加血 &7(+{hearts} 颗心) 并播放音效（消息可在语言文件修改）。

游戏总时长限制

  • config.yml → game-duration-limit: 60（单位仅分钟）。
  • 游戏进行到时限后强制结算（结算流程与正常分出胜负一致）。
  • 设为 <=0 关闭限制。
  • 适用场景：防止双方龟缩不出导致一局挂机数小时；默认 60 分钟与床摧毁（45 分钟）+ 游戏结束（15 分钟）的事件链总长一致。

隐身增强

  • config.yml → invisibility-enhance.enabled: true（默认开启）。
  • 喝下隐身药水后：
    • 非队友完全看不到该玩家，包括其手持物品（原版隐身手持物品会暴露）。
    • 队友可以看到其头顶名字标签，方便队内识别。
    • 隐身玩家未蹲下时持续向队友发送粒子效果，蹲下即隐藏粒子——蹲下反而不暴露，比原版疾跑粒子更实用（原版疾跑时才喷粒子，本功能反其道而行）。
  • 粒子参数：particle-interval: 4（发送间隔 tick）、particle-amount: 3（每次数量）。
  • 性能优化：隐身粒子仅发送给队友；隐身玩家名牌在 Tab 列表按队伍区分显示（BwTabList）。

重生时间减少增益开关

  • config.yml → respawn-time-reduction-enabled: true（默认开启）。
  • 设为 false 后，队伍升级中的“重生时间减少”不再生效（购买项仍显示与否取决于 upgrades2.yml / upgrades3.yml 的配置，但效果关闭）。
  • 适用场景：不希望后期团灭方过快反扑的服务器可关闭。

4/5 级资源点（钻石 / 绿宝石 Tier IV/V）

  • generators.yml 内置默认值：钻石 IV 级 1800 秒（30 分钟）、V 级 2520 秒（42 分钟）；绿宝石 IV 级 2160 秒（36 分钟）、V 级 2880 秒（48 分钟）。
  • IV/V 级事件显示在计分板事件行（“钻石 IV 级”等）。
  • config.yml → generator-tier-4-5-enabled: false 可整体关闭 IV/V 级。
  • 所有 delay / amount / spawn-limit / start 均可修改，详见 配置文件详解。

胜利用时显示

  • config.yml → win-time-display: true（默认开启）。
  • 胜利副标题显示“获得胜利, 用时”。
  • 自定义消息：语言文件 GAME_END_WIN_TIME_SUBTITLE，占位符 {team}（获胜队伍）、{time}（用时）。简中默认：&a&l{team} &7获得胜利, 用时 &f{time}。

等级显示模式

  • config.yml → levels-display-mode：
    • fancy（默认）：原有彩色阶数 / 星级显示。
    • simple：纯色简版显示，适合搭配自定义聊天格式或低版本客户端。

语言精简

  • 语言系统仅保留简体中文（zh_cn）、繁体中文（zh_tw，26.9 新增）、英文（en），移除其余 11 种语言。
  • config.yml 的 language 与 /bw lang 均只能在这三种中选择。

常见问题 FAQ

新手服主请先阅读 详细使用教程。本页收录安装后与日常运维中最常见的问题。

授权与启动

Q：插件启动时报错 "No license key configured"？
A：本插件为付费授权插件。请在 plugins/BedWarsHeypixel/config.yml 的 license-key 中填写有效的授权密钥，并重启服务端。密钥为空、无效或校验失败时插件会输出错误日志并自动禁用。

Q：授权验证失败怎么办？
A：检查密钥是否复制完整（无多余空格 / 换行）、网络是否可访问验证服务器；确认密钥与当前服务器匹配。修改后重启服务端（授权验证发生在插件启用阶段，/bw reload 不能代替）。

Q：插件没有生成配置文件？
A：确认插件 jar 已放入 plugins 文件夹且服务端启动成功；授权验证通过前插件可能不会生成完整配置。先解决授权问题再重启。

配置与重载

Q：修改了配置需要重启服务端吗？
A：不需要，使用 /bw reload 即可热重载全部配置文件（含 26.9 新增的 healthadd.yml、fastbuy.yml）。但 license-key、serverType 等启动级选项修改后需要重启。

Q：26.9 升级后我的旧 config.yml 会怎样？
A：首次以 26.9 启动时会自动补全新增配置项（game-duration-limit、win-time-display、respawn-time-reduction-enabled、generator-tier-4-5-enabled、levels-display-mode、invisibility-enhance.*），并自动生成 healthadd.yml 与 fastbuy.yml。已有自定义值不会被覆盖。

Q：generators.yml 里没有 tierIV/tierV 配置节？
A：26.9 起首次启动会自动写入默认值（钻石 IV 1800 秒 / V 2520 秒；绿宝石 IV 2160 秒 / V 2880 秒）。若文件为更早版本生成，可按 配置文件详解 中的示例手动补写，或删除该文件重新生成（注意先备份自定义内容）。

版本兼容

Q：支持哪些 Minecraft 版本？
A：1.8.8 ~ 1.21.4。26.9 新增 1.20.5 / 1.20.6 / 1.21 / 1.21.1 / 1.21.2 / 1.21.3 / 1.21.4 的支持。

Q：从 1.20.4 升级到 1.20.5+ 后要注意什么？
A：① 物品标识改用 PersistentDataContainer，与旧版本物品 tag 不互通；② 银鲛鱼 / 铁傀儡召唤物改用原版 AI，行为略有差异。详见 版本兼容性。

Q：编译插件需要什么 JDK？
A：构建需要 JDK 21；运行服务器本身按其对应核心的要求选择 Java 版本即可。

竞技场搭建

Q：如何快速搭建一个竞技场？
A：依次执行 /bw setLobby → /bw setupArena <名称> → /bw autoCreateTeams <数量> → 在世界中按搭建命令设置出生点、床、商店、升级 NPC、资源生成器等 → /bw save → /bw enableArena <名称>。完整分步教程见 详细使用教程。

Q：执行搭建命令提示未在搭建会话中？
A：搭建命令必须在 /bw setupArena <名称> 进入的搭建世界内使用，不能在大厅或其他世界执行。

Q：/bw save 后竞技场没出现在列表里？
A：用 /bw arenaList 检查是否保存成功；新保存的竞技场默认禁用，需 /bw enableArena <名称> 启用后才会开放加入。

Q：设置主大厅时报错？
A：/bw setLobby 需要在主大厅世界内（非竞技场世界）执行；BUNGEE 模式下无需设置。

26.9 新功能

Q：事件加血为什么不触发？
A：检查 healthadd.yml：① health-add.enabled 是否为 true；② events 下是否配置了合法事件（时间为 0 或血量 amount <= 0 的事件会被忽略）；③ 修改后是否执行了 /bw reload。加血事件在游戏开始后计时，等待大厅内不会触发。

Q：如何关闭事件加血？
A：将 healthadd.yml 中 health-add.enabled 设为 false，然后 /bw reload。

Q：快捷栏预设的红石图标不显示 / 想换个位置？
A：确认 fastbuy.yml 中 enabled: true；图标位置由 icon.slot 控制（默认 45），修改后 /bw reload。图标材质可通过 icon.material 更换。

Q：快捷栏预设重进服务器后设置丢了？
A：这是已知限制——该功能为测试阶段，预设数据按玩家保存在内存中，重进服务器后需重新设置。后续版本会改善。

Q：游戏到 60 分钟还没分出胜负怎么办？
A：26.9 起默认 game-duration-limit: 60，到时自动强制结算。若你希望更长 / 更短，修改 config.yml 中该值（单位分钟）；设为 <=0 则关闭限时。

Q：如何关闭“重生时间减少”团队升级？
A：config.yml 中 respawn-time-reduction-enabled: false，然后 /bw reload。

Q：如何关闭 4/5 级钻石绿宝石资源点？
A：config.yml 中 generator-tier-4-5-enabled: false（整体关闭），或在 generators.yml 中调整 IV/V 级的 start 时间。

Q：胜利后副标题想改文案？
A：语言文件中修改 GAME_END_WIN_TIME_SUBTITLE，占位符 {team} 为获胜队伍、{time} 为用时；想彻底关闭显示可将 config.yml 的 win-time-display 设为 false。

Q：等级显示太花哨，想要简洁版？
A：config.yml 中 levels-display-mode: simple（默认 fancy 彩色阶数 / 星级）。

Q：Shift+点击购买一组的扣费怎么算？
A：26.9 起按比例计价：商品单价 × 购买数量。例如羊毛 16 个卖 4 铁，Shift+点击买 64 个扣 16 铁。

新增功能

1. 快捷栏预设（测试阶段功能，fastbuy.yml）

  • 快捷购买界面新增红石图标（默认槽位 45，可通过 icon.slot 修改），点击打开预设设置界面。
  • 可为每个商店类别设置“购买后物品自动放入的快捷栏槽位（0-8）”，之后购买该类别物品时自动移位到指定槽位（若目标槽位已有物品则交换）。
  • ⚠️ 本功能处于测试阶段。fastbuy.yml 内含总开关 enabled 与全部界面文本 / 图标配置。
  • 预设数据按玩家保存在内存中，玩家重新进入服务器后需重新设置。

2. 事件加血（healthadd.yml，新建配置文件）

  • 可配置游戏开始后 1~4 次全体加血事件，或完全关闭。
  • 默认 2 次（开局后第 5 分钟、第 10 分钟），每次默认 +5 颗心（amount=10，单位为半心，可修改）。
  • 每次的触发时间（time-minutes / time-seconds）与血量（amount）均可单独配置。
  • 自动集成到游戏计分板事件显示：当加血时间早于下一个事件链事件时，事件行显示加血事件倒计时。
  • 触发时全竞技场广播提示并播放音效。

3. 游戏总时长限制（config.yml：game-duration-limit）

  • 默认 60（分钟），游戏进行到时限后强制结算。
  • 单位仅为分钟，设为 <=0 时关闭限制。

4. 隐身增强（config.yml：invisibility-enhance）

  • invisibility-enhance.enabled=true（默认开启）。
  • 玩家喝下隐身药水后，非队友完全看不到该玩家（包括手持物品）。
  • 队友可以看到其头顶名字标签，方便队内识别。
  • 隐身玩家未蹲下时持续向队友发送粒子效果（蹲下即隐藏粒子），比原版疾跑粒子更实用。
  • 粒子参数可调：particle-interval=4（发送间隔）、particle-amount=3（粒子数量）。

5. 重生时间减少增益开关（config.yml：respawn-time-reduction-enabled）

  • 默认 true。
  • 关闭后，“重生时间减少”团队升级将不再生效。

6. 4/5 级资源点级别（钻石 / 绿宝石 Tier IV/V）

  • generators.yml 新增默认值：
    • 钻石：IV 级 1800 秒出现，V 级 2520 秒出现。
    • 绿宝石：IV 级 2160 秒出现，V 级 2880 秒出现。
    • 均可自行修改。
  • config.yml 新增 generator-tier-4-5-enabled=true，设为 false 可整体关闭 IV/V 级资源点。

7. 胜利用时显示开关（config.yml：win-time-display）

  • 默认 true，胜利副标题显示“获得胜利, 用时”。
  • 消息可在语言文件 GAME_END_WIN_TIME_SUBTITLE 中自定义，支持 {team} / {time} 占位符。

8. 等级显示模式（config.yml：levels-display-mode）

  • fancy：原有彩色阶数 / 星级显示（默认）。
  • simple：纯色简版显示。

9. 新版本适配

  • 新增支持 Minecraft 1.20.5、1.20.6、1.21、1.21.1、1.21.2、1.21.3、1.21.4（此前最高 1.20.4）。

10. 语言精简

  • 语言系统仅保留简体中文（zh_cn）、繁体中文（zh_tw，新增）、英文（en），移除其余 11 种语言。

BUG 修复

  1. 修复 Shift+点击购买一组只扣除 1 份资源的问题——现按比例计价（例：羊毛 16 个 / 4 铁，Shift+点击买 64 个扣 16 铁）。
  2. 修复 debug 模式 /bw time add 后事件系统卡死、游戏永不结束的 bug——倒计时被减到 0 后事件不再推进；现在计数归零立即推进事件、倒计时钳制最小 1 秒、单次加时不超过当前阶段剩余时间，重复输入可继续推进。
  3. 修复 ChunkLoad 监听器在异步线程调用实体 API 的问题——改回主线程执行。
